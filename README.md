# NeonDrive — оболочка для Android-магнитол

## Навигация без интернета

В машине сеть пропадает ровно тогда, когда навигация нужнее всего. Оболочка
работает офлайн целиком, но два файла нужно положить на устройство самому —
в APK они не поместятся.

Оба лежат в папке приложения, видимой с компьютера по USB:
`Android/data/com.neondrive.launcher/files/`

### Карта — 304 МБ, вся Беларусь

```
https://download.mapsforge.org/maps/v5/europe/belarus.map
```

Скачать и положить в подпапку `map/`. Затем включить в оболочке:
**Настройки → Навигация → Карта без интернета**.

Соседние страны кладутся туда же и показываются как одна карта — при поездке
за границу достаточно докинуть ещё один файл.

Почему один файл, а не «скачанные тайлы»: карта здесь не хранится картинками,
а рисуется на устройстве из геометрии дорог, поэтому в 304 МБ помещаются сразу
все масштабы. Тот же охват растровыми тайлами до рабочего зума навигации занял
бы около 60 ГБ — 3,5 миллиона картинок, — а массовая выкачка тайлов с серверов
OpenStreetMap вдобавок запрещена правилами проекта.

Плата: рисование нагружает процессор ГУ сильнее готовых картинок. Нарисованное
складывается в кэш, так что знакомые улицы появляются мгновенно, а первый
проезд по новому району чуть медленнее сетевой карты. Поэтому это переключатель,
а не автоматика.

### Маршруты — граф GraphHopper

Строится на компьютере: импорт `.osm.pbf` требует нескольких гигабайт
оперативной памяти, которых на магнитоле нет.

```bash
wget https://download.geofabrik.de/europe/belarus-latest.osm.pbf
wget https://github.com/graphhopper/graphhopper/releases/download/1.0/graphhopper-web-1.0.jar
java -Xmx4g -jar graphhopper-web-1.0.jar import belarus-latest.osm.pbf
```

Получившуюся папку `belarus-latest-gh` целиком скопировать в подпапку `graph/`.

Зависимость GraphHopper по умолчанию закомментирована в
`app/build.gradle.kts` — она заметно утяжеляет сборку, поэтому включается
осознанно. Пока она выключена, оболочка честно пишет об этом в настройках и
строит маршруты через сеть.

### Камеры и ограничения скорости

Свои базы от радар-детекторов (`.csv` в формате TomTom или `.ov2`) кладутся в
подпапку `poi/` и работают наравне с данными OpenStreetMap, в том числе без
сети.

## Голос — «Елисей»

Оболочка понимает голосовые команды: адрес назначения, музыка, звонки. Команда
начинается с обращения — «Елисей, поехали домой», «Елисей, ближайшая заправка»,
«Елисей, позвони Ивану».

Распознавание работает офлайн, на самой магнитоле. Модель языка в APK не
помещается — она весит около 45 МБ, — поэтому кладётся на устройство отдельно,
тем же способом, что карта и граф маршрутов:

```
https://alphacephei.com/vosk/models   →   vosk-model-small-ru-0.22.zip
```

Распакованную папку положить в подпапку `vosk/`, туда же, в
`Android/data/com.neondrive.launcher/files/`.

Постоянное прослушивание («Елисей» без нажатия чего-либо) выключено по
умолчанию: открытый микрофон — осознанный выбор владельца машины, а не
настройка по умолчанию. Включается в **Настройки → Навигация → Голосовое
управление**. Без него голос тоже работает — от кнопки руля «Голосовой
помощник» и от кнопки микрофона в поиске адреса.

Без скачанной модели оболочка переходит на системный распознаватель Android.
Он есть не на всех магнитолах (на ГУ без сервисов Google его обычно нет вовсе)
и не умеет ждать ключевое слово, поэтому команду там придётся начинать с
кнопки. Что именно доступно на конкретном устройстве, оболочка пишет в
настройках.

Зависимость `vosk-android` — единственная нативная библиотека в проекте, около
10 МБ на архитектуру; в сборку включены только `armeabi-v7a` и `arm64-v8a`.
Связь с ней сделана рефлексией, поэтому строку в `app/build.gradle.kts` можно
закомментировать: оболочка соберётся и будет работать, потеряв только ожидание
ключевого слова.

## Сборка

APK собирается через GitHub Actions (`.github/workflows/build-apk.yml`) или
локально скриптами `build-local.bat` / `build-local.ps1`.

Ключ подписи лежит в репозитории намеренно: он не даёт доступа ни к чему, кроме
права переустановки этого же пакета поверх себя, зато все сборки — локальные и
из Actions — получают одинаковую подпись, и обновления ставятся поверх старой
версии без удаления.
