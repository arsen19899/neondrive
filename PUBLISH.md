# Как получить APK через GitHub — без установки чего-либо

Сборка идёт на серверах GitHub. На вашем компьютере не нужны ни Android Studio,
ни Java, ни SDK. Нужен только аккаунт GitHub и браузер.

Проект уже подготовлен: git-репозиторий инициализирован, первый коммит сделан
(51 файл), workflow лежит в `.github/workflows/build-apk.yml`.

---

## Путь A — через браузер, без git (проще)

**1. Создать репозиторий**

Откройте <https://github.com/new>:

* **Repository name** — `neondrive`
* **Public** или **Private** — оба подойдут. Public даёт неограниченные минуты
  сборки, Private — 2000 минут в месяц бесплатно (одна сборка ≈ 4 минуты).
* Галочки «Add a README», «Add .gitignore», «Choose a license» — **не ставить**.
* `Create repository`.

**2. Загрузить файлы**

На странице пустого репозитория нажмите **uploading an existing file**
(ссылка в строке «…or upload an existing file»).

Откройте `D:\lawch\NeonDrive` в проводнике, выделите **всё содержимое папки**
(Ctrl+A) и перетащите в окно браузера. Дождитесь, пока загрузятся все файлы,
затем **Commit changes**.

**3. Проверить, что папка `.github` доехала**

Windows скрывает папки, начинающиеся с точки, и при перетаскивании она может
не попасть в загрузку. В списке файлов репозитория должна быть строка `.github`.

Если её нет — создайте файл вручную:

* **Add file → Create new file**
* в поле имени вставьте путь целиком: `.github/workflows/build-apk.yml`
  (слэши сами превратятся в папки)
* вставьте содержимое файла `.github/workflows/build-apk.yml` из папки проекта
* **Commit changes**

**4. Разрешить Actions публиковать релиз** *(необязательно, но удобно)*

**Settings → Actions → General → Workflow permissions** →
выбрать **Read and write permissions** → **Save**.

Без этого сборка всё равно пройдёт, APK будет в артефактах — просто не появится
постоянная ссылка на релиз.

**5. Забрать APK**

Вкладка **Actions** → сборка «Сборка APK» запустится сама. Первый прогон
занимает 4–7 минут (качается SDK и зависимости).

Когда напротив появится зелёная галочка:

* **Артефакты** — откройте сборку, внизу блок **Artifacts** → `NeonDrive-apk`
  (скачается zip с двумя APK);
* **Релиз** — вкладка **Releases** → `NeonDrive — последняя сборка`. Прямую ссылку
  на `NeonDrive-release.apk` оттуда удобно открыть **прямо в браузере магнитолы**
  и поставить без компьютера и кабеля.

## Путь B — через командную строку (3 команды)

Если git на компьютере есть. Репозиторий уже инициализирован и закоммичен,
осталось только привязать его к GitHub:

```bash
cd D:\lawch\NeonDrive
git remote add origin https://github.com/ВАШ_ЛОГИН/neondrive.git
git push -u origin main
```

Дальше — то же самое: вкладка **Actions**, ждём галочку, забираем APK.

## Обновление без удаления старой версии

Раньше каждая сборка на GitHub Actions подписывалась новым случайным ключом
(автосоздавался на чистой виртуалке), поэтому Android отказывался ставить
новый APK поверх старого — приходилось сначала вручную удалять NeonDrive.
Теперь release подписывается одним и тем же ключом из `keystore/`, закреплённым
в репозитории, — и локальные сборки, и Actions используют его. Обновления
ставятся поверх старой версии как обычно, без удаления.

**Важно:** если на устройстве уже стоит версия, собранная до этого исправления
(подписана старым случайным ключом), самое первое обновление всё ещё потребует
удалить её вручную — подписи не совпадают один раз. Все последующие обновления
после этого будут ставиться поверх без вопросов.

## Установка на головное устройство

1. Скачать `NeonDrive-release.apk` на магнитолу (браузером по ссылке из релиза,
   через USB-флешку или `adb install -r NeonDrive-release.apk`).
2. Открыть файл встроенным файловым менеджером, разрешить установку из этого
   источника, установить.
3. **Настройки Android → Приложения по умолчанию → Главный экран** → NeonDrive.
4. **Настройки → Уведомления → Доступ к уведомлениям** → включить NeonDrive.
   Без этого не будет реакции на уведомления телефона и управления Яндекс.Музыкой.
5. При первом запуске выдать разрешения: геолокация, музыка, телефон, Bluetooth.

Пункты 3–5 продублированы внутри оболочки: **Настройки оболочки → Система**.

## Если сборка упала

Откройте упавший шаг во вкладке Actions — там полный лог. Типичные причины:

| Что в логе | Что делать |
|---|---|
| `SDK location not found` | Шаг «Android SDK» не отработал — перезапустите workflow кнопкой **Re-run all jobs** |
| `Could not resolve …` | Временный сбой сети GitHub, помогает **Re-run all jobs** |
| `403` на шаге релиза | Не выданы права из пункта 4. APK при этом лежит в артефактах |
| Ошибка компиляции Kotlin | Пришлите текст ошибки — поправлю |

Последующие сборки быстрее: Gradle-кэш переиспользуется.
